========================================================================
                         GIT COMMANDS CHEAT SHEET
========================================================================

1. SETUP & VERSION CHECK
- git --version
  Checks if Git is installed and displays the current version.
- git config --global user.name "Your Name"
  git config --global user.email "you@example.com"
  Sets your author name and email globally for all future commits.
- git config --list
  Displays all configured Git settings for the current user.

2. REPOSITORY CREATION & REMOTE MANAGEMENT
- git init
  Initializes a normal local directory as a new Git repository.
- git clone <url>
  Downloads a complete copy of an existing remote repository locally.
- git remote add origin <url>
  Links your local repository to a remote repository under 'origin'.
- git remote -v
  Lists all remote repository URLs connected to your local repository.
- git remote show origin
  Displays detailed information about the remote repository.
- git remote rename origin upstream
  Renames an existing remote alias (e.g., from 'origin' to 'upstream').
- git remote set-url origin <new_url>
  Updates the linked remote URL when a repository address changes.
- git remote remove origin
  Disconnects and removes a remote repository from local configuration.

3. STAGING & COMMITTING (LOCAL SAVE)
- git status
  Displays modified, untracked, and staged files in the working directory.
- git add <file>  /  git add .
  Moves a specific file (<file>) or all changes (.) to the staging area.
- git commit -m "message"
  Records staged changes permanently into the local repository history.

4. SYNCING WITH REMOTE (PUSH, FETCH, PULL, REBASE)
- git push origin main
  Uploads local commits to the remote repository's 'main' branch.
- git push --set-upstream origin feature-branch
  Pushes a new branch for the first time and sets up a tracking link.
- git fetch origin  /  git fetch origin <branch>
  Downloads latest remote changes without merging them into local code.
- git pull origin main
  Fetches latest remote updates and merges them into your local branch.
- git fetch origin  +  git rebase origin/main
  Reapplies local commits on top of latest remote commits linearly.

5. BRANCHING, MERGING & CLEANUP
- git branch  /  git branch -a  /  git branch -r
  Lists local branches, all branches (-a), or remote branches (-r).
- git branch <name>
  Creates a new branch without switching to it.
- git checkout <branch>  /  git checkout -b <new-branch>
  Switches to an existing branch; -b creates and switches immediately.
- git merge <branch-name>
  Integrates changes from the specified branch into the current branch.
- git branch --merged
  Lists branches that have already been merged into the current branch.
- git branch -d <branch>  /  git branch -D <branch>
  Deletes a merged branch (-d) or force-deletes an unmerged branch (-D).
  (Delete multiple at once: git branch -d branch1 branch2 branch3)
- git remote prune origin
  Removes stale local references to branches deleted on the remote.

6. VIEWING HISTORY & TRACKING LINES
- git log  /  git log --oneline
  Displays commit history (--oneline shows a compact one-line summary).
- git diff
  Shows line-by-line differences in unstaged files vs. the last commit.
- git show <commit>
  Displays metadata and exact line changes for a specific commit hash.
- git blame <filename>
  Shows who last modified each line of a file and in which commit.

7. UNDOING MISTAKES, RECOVERY & STASH
- git restore <filename>
  Discards unstaged local edits and reverts the file to the last commit.
- git reset <file>  /  git reset --hard
  Unstages a file without losing edits; --hard wipes all uncommitted work.
- git commit --amend -m "New message"
  Edits the commit message of the most recent unpushed commit.
- git revert <commit>
  Creates a new commit that safely undoes changes from a past commit.
- git reflog  +  git checkout -b <branch> <commit_hash>
  Recovers a deleted branch using its last commit hash from the reflog.
- git filter-branch --force --index-filter \
  "git rm --cached --ignore-unmatch secrets.txt" \
  --prune-empty --tag-name-filter cat -- --all
  Permanently removes a sensitive file from the entire commit history.
- git stash  &  git stash apply
  Temporarily saves uncommitted changes (stash) and restores them (apply).

8. .GITIGNORE & MANUAL MERGE CONFLICT RESOLUTION
- .gitignore File
  Create with 'touch .gitignore' and add patterns (e.g., *.log, temp/, 
  secret_file.txt) so Git ignores those files and keeps them untracked.
- Resolving Merge Conflicts
  Open the conflicted file, keep the desired code, remove all conflict 
  markers (<<<<<<<, =======, >>>>>>>), then run 'git add <file>' and 
  'git commit' to complete the merge.
========================================================================

maven java

Phase 1: Eclipse JDK One-Time Setup (Do This Before Creating the Project!)
DO THIS STEP FIRST SO YOU NEVER GET A COMPILER ERROR:
1. Open Window -> Preferences from the top menu in Eclipse.
2. On the left side, go to Java -> Installed JREs.
3. On the right side list, tick the checkbox next to jdk-21.0.13.9-hotspot (untick the default jre).
4. Click Apply and Close at the bottom.

Phase 2: Maven Java Project Creation
1. From the top menu, click File -> New -> Other...
2. Select Maven -> Maven Project and click Next.
3. Click Next again to reach the Select an Archetype screen.
4. Type org.apache.maven in the Filter box, and untick (remove) the "Show the last version of Archetype only" checkbox at the bottom.
5. In the list, select org.apache.maven.archetypes -> maven-archetype-quickstart (Version 1.4) and click Next.
6. Enter the details and click Finish:
   - Group Id: com.app.demo
   - Artifact Id: <your_project_name> (e.g., alice)
7. Wait 10 seconds until the green progress bar in the bottom-right corner reaches 100% (if the Console asks Y: :, type Y and press Enter).

Phase 3: Build Path & Run Configuration Fix (Zero-Error Guarantee)
Right after creating the project, configure these 2 settings before running Maven:

1. Project Build Path Fix:
   - Right-click on your project -> Build Path -> Configure Build Path...
   - In the Libraries tab, select JRE System Library and click Edit...
   - Select Alternate JRE, choose jdk-21.0.13.9-hotspot from the dropdown -> Finish -> Apply and Close.

2. Maven Build Run Configuration:
   - Right-click on your project -> Run As -> Run Configurations...
   - Double-click on Maven Build on the left side.
   - In the Main tab:
     * Base directory: Click Workspace... and select your project (e.g., alice).
     * Goals: Type clean install
   - In the JRE tab:
     * Select Alternate JRE and choose jdk-21.0.13.9-hotspot from the dropdown.
   - Click Apply at the bottom and then click Run.

Phase 4: Verify JAR File & Output
1. Once BUILD SUCCESS appears in the Console, click on your project in Project Explorer and press F5 (Refresh).
2. Expand the target/ folder to see the generated <project_name>-0.0.1-SNAPSHOT.jar file (e.g., alice-0.0.1-SNAPSHOT.jar).
3. To check the output, navigate to src/main/java -> com.app.demo.<project_name> -> App.java, right-click -> Run As -> Java Application — Hello World! will print in the Console.

Phase 5: Push Project to GitHub (Clean Method)
1. On GitHub.com, click New repository and enter a repo name (e.g., maven-java-lab).
2. In the Add .gitignore dropdown, select Maven and click Create repository.
3. Click the Code button and copy the repository HTTPS / SSH URL.
4. Open Windows File Explorer, go to your project folder (C:\Users\alice\Downloads\<project_name>), right-click on an empty space -> Open Git Bash here.
5. Run this command in Git Bash:
   git clone <copied_github_repo_url>
6. In File Explorer, copy (Ctrl + C) the src folder and pom.xml file from your project folder (<project_name>), and paste (Ctrl + V) them inside the newly cloned repo folder.
7. Go back to Git Bash, navigate into the cloned folder, and push:
   cd <cloned_repo_folder_name>
   git add .
   git commit -m "Maven Java project"
   git push
8. Refresh your GitHub browser page to see your src folder and pom.xml uploaded cleanly.

Pro-Tip (Alternative 1-Line Terminal Build): If the Maven button in Eclipse UI ever fails to build, open Git Bash inside your project folder and run this single line — it will build the .jar file in 10 seconds:
JAVA_HOME="/c/Program Files/Eclipse Adoptium/jdk-21.0.13.9-hotspot" mvn clean install

docker basics

Part 1: Docker CLI Commands with Redis

Step 1: Pull the Redis Image
Command:
docker pull redis
(Downloads the official redis image from Docker Hub to your local system.)

Step 2: Run a Redis Container
Command:
docker run --name my-redis -d redis
(Creates and starts a container named my-redis from the redis image in the background using -d.)

Step 3: Check Running Containers
Command:
docker ps
(Lists all currently running containers — verify that my-redis is up.)

Step 4: Access Redis CLI Inside the Container
Command:
docker exec -it my-redis redis-cli
(Opens the Redis command-line tool inside the running container.)

Run these commands inside the 127.0.0.1:6379> prompt:
SET name "Alice"
GET name
exit
(Saves the key-value pair, retrieves "Alice", and exits the Redis CLI.)

Step 5: Stop the Redis Container
Command:
docker stop my-redis
(Stops the running my-redis container without deleting it.)

Step 6: Restart the Redis Container
Command:
docker start my-redis
(Restarts the stopped my-redis container.)

Step 7: Remove the Redis Container
Commands:
docker stop my-redis
docker rm my-redis
(Note: You must stop the container first before permanently deleting it with docker rm.)

Step 8: Remove the Redis Image
Command:
docker rmi redis
(Deletes the redis image from your local system.)


docker hub and dockerfile

Part 2: Working with Dockerfile (Build, Commit, Push & Test)
(Note: Replace <your_dockerhub_username> with your own Docker Hub username, e.g., alice123)

Step 1: Set Up Your Folder
1. Create a folder and navigate into it (Windows Git Bash):
   mkdir -p /c/DockerProjects/Redis
   cd /c/DockerProjects/Redis

Step 2: Write the Dockerfile
1. Inside the folder, create a file named Dockerfile (no extension) with the following content:
   FROM redis:latest
   CMD ["redis-server"]

   (Quick terminal command to create it directly:
   printf 'FROM redis:latest\nCMD ["redis-server"]\n' > Dockerfile)

Step 3: Build & Run Custom Image
1. docker build -t redisnew .
   (Builds a Docker image named redisnew using the Dockerfile in the current directory.)

2. docker run --name myredisnew -d redisnew
   (Starts a background container named myredisnew from the redisnew image.)

3. docker ps
   (Lists running containers — note down the CONTAINER ID of myredisnew.)

Step 4: Stop, Login, Commit & Push to Docker Hub
4. docker stop myredisnew
   (Stops the running myredisnew container.)

5. docker login
   (Logs into your Docker Hub account so you can push images.)

6. docker ps -a
   (Lists all containers including stopped ones — copy the CONTAINER ID of myredisnew.)

7. docker commit <container_id_of_myredisnew> <your_dockerhub_username>/redis1
   (Saves a snapshot of the container as a new image named <your_dockerhub_username>/redis1.)

8. docker images
   (Lists all local images — verify <your_dockerhub_username>/redis1 is listed.)

9. docker push <your_dockerhub_username>/redis1
   (Uploads your custom image to Docker Hub.)

Step 5: Local Cleanup & Logout
10. docker rm <container_id_of_myredisnew>
    (Deletes the stopped myredisnew container.)

11. docker rmi <your_dockerhub_username>/redis1
    (Deletes the local image from your system.)

12. docker ps -a
    (Confirms the container has been removed.)

13. docker logout
    (Logs out from Docker Hub and removes stored credentials.)

Step 6: Pull Back from Docker Hub & Verify Inside Redis CLI
14. docker pull <your_dockerhub_username>/redis1
    (Downloads your custom image back from Docker Hub.)

15. docker run --name myredis -d <your_dockerhub_username>/redis1
    (Starts a new background container named myredis from the pulled image.)

16. docker exec -it myredis redis-cli
    (Opens the Redis CLI inside the running container.)

17. SET name "Abcdef"
    (Saves the key-value pair inside Redis.)

18. GET name
    (Retrieves and prints "Abcdef".)

19. exit
    (Exits the Redis CLI.)

Step 7: Final Cleanup
20. docker ps -a
    (Lists all containers — note down the CONTAINER ID of myredis.)

21. docker stop myredis
    (Stops the running myredis container.)

22. docker rm <container_id_of_myredis>
    (Deletes the stopped myredis container.)

23. docker images
    (Lists remaining images on your system.)

24. docker rmi <your_dockerhub_username>/redis1
    (Deletes the pulled image from your local system.)

Exercise 1: WordPress + MySQL Setup (ARM64 / Apple Silicon Compatible)

1. Create a file named docker-compose.yml inside your project folder with the following content
   (Using mysql:8.0 which natively supports ARM64, or add platform: linux/amd64 if using mysql:5.7):

version: '3.8'
services:
  wordpress:
    image: wordpress:latest
    ports:
      - "8085:80"
    environment:
      WORDPRESS_DB_HOST: db:3306
      WORDPRESS_DB_USER: wordpress
      WORDPRESS_DB_PASSWORD: wordpress
      WORDPRESS_DB_NAME: wordpress
    depends_on:
      - db
  db:
    image: mysql:8.0
    platform: linux/arm64
    environment:
      MYSQL_ROOT_PASSWORD: rootpassword
      MYSQL_DATABASE: wordpress
      MYSQL_USER: wordpress
      MYSQL_PASSWORD: wordpress

(Note: If your exam strictly requires mysql:5.7 on an ARM64 machine, replace the db image block with:
  db:

    platform: linux/amd64

      MYSQL_ROOT_PASSWORD: rootpassword
      MYSQL_DATABASE: wordpress
      MYSQL_USER: wordpress
      MYSQL_PASSWORD: wordpress)

3. Open http://localhost:8085 in your browser to see the WordPress installation screen.

Week 9: Scripted / Declarative Jenkins Pipeline & Build Triggers

Prerequisite: Ensure Maven tool is configured as "MAVEN-HOME" (or update the tools block name to match your Jenkins Tools configuration).

Step 1: Create Pipeline Job
1. Open Jenkins (http://localhost:8080) -> Click "New Item".
2. Enter name: Maven_Scripted_Pipeline -> Select "Pipeline" -> Click OK.

Step 2: Configure General & Build Triggers
1. Description: Scripted Maven Pipeline with Build Triggers
2. Under "Build Triggers" (choose as required by your exam/lab):
   - Option A (Poll SCM — checks GitHub periodically for new commits):
     * Tick "Poll SCM" -> Schedule: H/5 * * * *   (checks every 5 minutes)
   - Option B (Build periodically — scheduled build, e.g., every day at 6 PM):
     * Tick "Build periodically" -> Schedule: 0 18 * * *
   - Option C (GitHub hook trigger — instant trigger via webhook):
     * Tick "GitHub hook trigger for GITScm polling"

Step 3: Add Pipeline Script
1. Scroll down to the "Pipeline" section:
   - Definition: Choose "Pipeline script"
2. Paste the following corrected script (replace <your_github_repo_url> and <repo_folder_name>):

pipeline {
    agent any
    tools {
        maven 'MAVEN-HOME'
    }
    stages {
        stage('git repo & clean') {
            steps {
                bat "if exist <repo_folder_name> rmdir /s /q <repo_folder_name>"
                bat "git clone <your_github_repo_url>"
                bat "mvn clean -f <repo_folder_name>"
            }
        }
        stage('install') {
            steps {
                bat "mvn install -f <repo_folder_name>"
            }
        }
        stage('test') {
            steps {
                bat "mvn test -f <repo_folder_name>"
            }
        }
        stage('package') {
            steps {
                bat "mvn package -f <repo_folder_name>"
            }
        }
    }
}

(Note: If Jenkins is running on Mac/Linux instead of Windows, replace "bat" with "sh" and use "rm -rf <repo_folder_name>".)

Step 4: Save, Run & Verify
1. Click Apply and Save.
2. Click "Build Now" on the left menu.
3. Verification: Stage View shows all 4 stages (git repo & clean, install, test, package) in GREEN, and the .jar/.war file is generated inside the target/ folder.
